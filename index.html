Screenshot tests that show what changed.

gleon compares the screenshots of your tests with your goldens. It finds real changes and ignores font differences between operating systems. Use the CLI with each test runner, or an SDK in your test framework.

Install the CLI See the products 
$ gleon test -- flutter test

$

One engine for all test runners

The CLI works with each test runner that writes PNG files. The SDKs work inside your test framework. All of them use the same Rust engine and the same .gleon/gleon.yaml file.

  • gleon CLI Available

    For each test runner that writes PNG files

    • A summary for each run, with one line for each failure
    • An HTML report that shows the golden, the candidate and the diff
    • Markdown, JUnit and JSON reports for your CI
    • A comment on the pull request. Write /gleon approve to commit the new goldens.
    • Goldens in Git, or manifests in Git and images in S3, R2 or Google Cloud Storage

gleon stage          # record
gleon diff           # compare

What changes when you use gleon

Most golden test suites have the same problems. This is what gleon does for each problem.

Without gleonWith gleon
A golden from macOS fails on Linux. Each operating system draws fonts differently.
Each golden records the platform that made it. gleon compares text strictly on that platform and ignores text on other platforms. Layout stays exact. You can update goldens on each operating system, without Docker.
A threshold of 1% lets a missing icon pass on a large screen.
In pixel mode, you set the ratio. In ssim mode, gleon uses the lowest local similarity. A small change on a large golden does not disappear in an average.
The test font draws each letter as the same box. The goldens cannot show text.
The SDK loads the real fonts of your app. gleon compares only the text that is really painted. Hidden pages cannot hide a change.
A failed CI job shows that something changed. It does not show where, or how near the other goldens were to failure.
gleon gives a summary for each run and an HTML report with the golden, the candidate and the diff. It writes a comment on the pull request. /gleon approve commits the new goldens. Metrics show the margin of each golden that passed.
The built-in comparison is slow. Most of the time goes to PNG encoding.
gleon compares raw pixels in Rust. It is 5 to 20 times faster than the built-in comparator, and ssim mode is as fast as exact mode.

How it works

Use three commands on your computer and one step in CI. Your test command does not change.

  1. Make a workspace

    gleon init makes the .gleon/gleon.yaml file. This file sets the comparison rules for your goldens. Without a tolerance, gleon compares exactly.

    # .gleon/gleon.yaml
baselines: goldens
fallback_platform: macos-aarch64
screenshots:
  - include: "**/test/**/*.png"
    mode: ssim # or exact, pixel
exclude:
  - "**/failures/**"

  2. Run your tests with gleon

    gleon records one run. It shows the totals and one line for each failure. It exits with the exit code of your tests.

    $ gleon test -- flutter test
Run run-20261020T101500Z-1a2b3c4d: 128 case(s): 125 passed, 3 failed (2 mismatch, 1 missing)
  test/goldens/counter_3: Mismatch: 0.0167% (1 of 6000px) differ (.gleon/runs/latest/cases/macos-aarch64/test/goldens/counter_3.json)

  3. Examine and approve

    The HTML report shows each failure with its golden, candidate and diff. gleon approve writes the accepted candidates over their goldens.

    $ gleon report html --out .gleon/runs/latest/report.html
$ gleon approve

In CI

The GitHub Action runs your tests. It writes the failures in a comment on the pull request and uploads the run. Write /gleon approve in the pull request to commit the new goldens. On other CI systems, use the JUnit report from gleon report junit.

- uses: gleon-rs/gleon@main
  with:
    command: verify
    test-command: flutter test

Speed and proof

Where it runs

You can record goldens on each of these platforms. Each golden records the platform that made it.

gleon CLI

  • gleon-macos-aarch64macOS on Apple silicon
  • gleon-linux-x86_64Linux x86_64, Ubuntu 26.04 or newer
  • gleon-windows-x86_64.exeWindows x86_64, no extra runtime

Flutter package

  • macOSarm64
  • Linuxx64 and arm64, glibc of Ubuntu 26.04 or newer
  • Windowsx64
  • Flutter3.50 or newer

Not supported: macOS on Intel, Linux with musl (for example Alpine), web builds and tests on a device. gleon compares PNG images.

What is open source

The comparison engine (gleon-engine, gleon-model, gleon-ffi) is MIT or Apache-2.0. The Flutter package is MIT. The CLI and gleon-core use the Business Source License 1.1. Each version becomes Apache-2.0 four years after its release, or on July 13, 2030, if that date is earlier.

Without a key, private CI shows a warning and continues. With --strict, the warning becomes exit code 42. In private CI without a key, use an official release that is less than 90 days old: older releases and builds from source stop with exit code 42. Read the full license.

Install

gleon CLI

Download the binary for your system from the releases page, or use gh:

gh release download --repo gleon-rs/gleon --pattern gleon-macos-aarch64
install -m 755 gleon-macos-aarch64 ~/.local/bin/gleon

On Linux, use gleon-linux-x86_64. On Windows, use gleon-windows-x86_64.exe. Each release has SHA256SUMS.txt and a build attestation for each file.

Homebrew support comes soon

Flutter package

Add the package as a dev dependency, then change one import:

flutter pub add dev:gleon
import 'package:flutter_test/flutter_test.dart';
import 'package:gleon/gleon.dart';

The package guide shows how to load the real fonts, set tolerances and configure a workspace.
